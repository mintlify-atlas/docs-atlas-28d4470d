By default, importing `@visactor/vchart` gives you a fully assembled instance — every chart type, every component, and every interaction are pre-registered via `vchart-all.ts`. This is the fastest way to get started, but it includes code you may never use. For production applications where bundle size matters, VChart provides a granular registration API: every chart type, axis, component, interaction, and environment has a dedicated `registerXxx` function. You collect only the ones you need and pass them as an array to `VChart.useRegisters([...])` before rendering any charts. This single call pattern is idempotent — calling the same register function more than once is safe — and integrates cleanly with any bundler's tree-shaking.

## Two Usage Patterns

<Tabs>
  <Tab title="Default (All Charts)">
    Import VChart's default export. Everything is pre-registered and ready to use. Best for prototyping or projects where bundle size is not a concern.

    ```ts
    // vchart/src/index.ts — re-exports from vchart-all.ts which
    // calls VChart.useRegisters([...everything...]) at module load time
    import VChart from '@visactor/vchart';

    const vchart = new VChart(
      { type: 'bar', data: [{ id: 'd', values: [{ x: 'A', y: 10 }] }], xField: 'x', yField: 'y' },
      { dom: 'container' }
    );
    vchart.renderAsync();
    ```

    <Note>
      The default import includes all 27+ chart types and all components. In a typical webpack or Rollup build this adds roughly 700 kB (minified + gzipped ~200 kB) to your bundle.
    </Note>
  </Tab>

  <Tab title="Selective (Tree-Shakeable)">
    Import `VChart` from its core module and call `useRegisters` with only what you need. Any module you do not import will be excluded from the final bundle.

    ```ts
    import { VChart } from '@visactor/vchart/esm/core';
    import { registerBarChart } from '@visactor/vchart/esm/chart/bar';
    import { registerCartesianLinearAxis, registerCartesianBandAxis }
      from '@visactor/vchart/esm/component/axis/cartesian';
    import { registerDiscreteLegend } from '@visactor/vchart/esm/component/legend';
    import { registerTooltip } from '@visactor/vchart/esm/component/tooltip';
    import { registerCartesianCrossHair } from '@visactor/vchart/esm/component/crosshair';
    import { registerLabel } from '@visactor/vchart/esm/component/label';
    import { registerCanvasTooltipHandler }
      from '@visactor/vchart/esm/plugin/components/tooltip-handler';
    import { registerAnimate } from '@visactor/vchart/esm/plugin/other';
    import { registerBrowserEnv } from '@visactor/vchart/esm/env';

    VChart.useRegisters([
      registerBarChart,
      registerCartesianLinearAxis,
      registerCartesianBandAxis,
      registerDiscreteLegend,
      registerTooltip,
      registerCartesianCrossHair,
      registerLabel,
      registerCanvasTooltipHandler,
      registerAnimate,
      registerBrowserEnv
    ]);

    const vchart = new VChart(
      { type: 'bar', data: [{ id: 'd', values: [{ x: 'A', y: 10 }] }], xField: 'x', yField: 'y' },
      { dom: 'container' }
    );
    vchart.renderAsync();
    ```

    <Tip>
      Alternatively, import from the top-level `@visactor/vchart` package (not the default export) and use named imports. Modern bundlers will tree-shake unused registers automatically as long as you avoid the default import path.
    </Tip>
  </Tab>
</Tabs>

## `VChart.useRegisters()`

The static `useRegisters` method is the single entry point for all selective registration. It accepts an array of zero-argument functions and calls each one:

```ts
// packages/vchart/src/core/vchart.ts
static useRegisters(comps: (() => void)[]) {
  comps.forEach((fn: () => void) => {
    if (typeof fn === 'function') {
      fn();
    } else {
      console.error('Invalid function:', fn);
    }
  });
}
```

Each register function internally calls `Factory.registerXxx(...)` to inject the feature into VChart's dependency-injection container. Call `useRegisters` once, before instantiating any `VChart` object.

<Accordion title="Axis Registers">

Cartesian and polar axes are registered independently. Include only the axis types your charts require.

| Function | Axis Type | Use With |
|---|---|---|
| `registerCartesianBandAxis` | Ordinal band axis | Bar, waterfall, histogram |
| `registerCartesianLinearAxis` | Continuous linear axis | Line, area, scatter |
| `registerCartesianLogAxis` | Logarithmic axis | Scatter with wide value ranges |
| `registerCartesianSymlogAxis` | Symmetric log axis | Data containing zero or negatives |
| `registerCartesianTimeAxis` | Time-based axis | Sequence, line with date fields |
| `registerPolarBandAxis` | Polar band axis | Rose, radar |
| `registerPolarLinearAxis` | Polar linear axis | Radar, rose |

```ts
import {
  registerCartesianBandAxis,
  registerCartesianLinearAxis,
  registerCartesianLogAxis,
  registerCartesianSymlogAxis,
  registerCartesianTimeAxis,
  registerPolarBandAxis,
  registerPolarLinearAxis
} from '@visactor/vchart';

VChart.useRegisters([
  registerCartesianBandAxis,
  registerCartesianLinearAxis
]);
```

</Accordion>

<Accordion title="Interaction Registers">

Interaction triggers are the built-in behaviours that respond to pointer events on chart elements. Register only the behaviours you need.

| Function | Trigger | Description |
|---|---|---|
| `registerElementActive` | `elementActive` | Sets an active state on the hovered element |
| `registerElementActiveByLegend` | `elementActiveByLegend` | Activates all elements belonging to a legend item on hover |
| `registerElementHighlight` | `elementHighlight` | Highlights the hovered element and dims others |
| `registerElementHighlightByLegend` | `elementHighlightByLegend` | Highlights all elements in the same legend group |
| `registerElementHighlightByGroup` | `elementHighlightByGroup` | Highlights elements sharing the same group key |
| `registerElementHighlightByKey` | `elementHighlightByKey` | Highlights elements sharing the same datum key |
| `registerElementHighlightByName` | `elementHighlightByName` | Highlights elements matching a mark name filter |
| `registerElementSelect` | `elementSelect` | Toggles a persistent selected state on click |
| `registerDimensionHover` | `dimensionHover` | Highlights all elements on the same axis dimension value |

```ts
import {
  registerElementActive,
  registerElementActiveByLegend,
  registerElementHighlight,
  registerElementHighlightByLegend,
  registerElementHighlightByGroup,
  registerElementHighlightByKey,
  registerElementHighlightByName,
  registerElementSelect,
  registerDimensionHover
} from '@visactor/vchart';

VChart.useRegisters([
  registerElementHighlightByLegend,
  registerElementSelect
]);
```

</Accordion>

<Accordion title="Environment Registers">

VChart runs in multiple JavaScript host environments. Each environment register loads the appropriate VRender rendering adapters. Call the one that matches your deployment target.

| Function | Environment | When to Use |
|---|---|---|
| `registerBrowserEnv` | Browser | Standard web browser (auto-selected by `VChart` constructor) |
| `registerNodeEnv` | Node.js | Server-side rendering, image export pipelines |
| `registerLarkEnv` | Lark / Feishu | Lark mini-program and Lark Block environments |
| `registerWXEnv` | WeChat | WeChat Mini Program (`wx` canvas API) |
| `registerTaroEnv` | Taro | Taro cross-platform mini-program framework |
| `registerTTEnv` | ByteDance | ByteDance / Douyin mini-program |
| `registerHarmonyEnv` | Harmony OS | Huawei HarmonyOS ArkTS environment |

```ts
import { registerBrowserEnv, registerNodeEnv } from '@visactor/vchart';

// In a browser application:
VChart.useRegisters([registerBrowserEnv]);

// In a Node.js SSR / export script:
VChart.useRegisters([registerNodeEnv]);
```

<Warning>
The default `VChart` constructor auto-registers `registerBrowserEnv` in browser environments and `registerNodeEnv` in Node.js. You only need these explicitly when using the tree-shakeable `VChart` core import (`@visactor/vchart/esm/core`) or when targeting mini-program runtimes.
</Warning>

</Accordion>

## Minimal Bundle Example

The following bundle is sufficient for a simple bar chart with a legend and tooltip in a browser — no map, no player, no brush, no markers:

```ts
import { VChart } from '@visactor/vchart/esm/core';
import { registerBarChart } from '@visactor/vchart/esm/chart/bar';
import {
  registerCartesianBandAxis,
  registerCartesianLinearAxis
} from '@visactor/vchart/esm/component/axis/cartesian';
import { registerDiscreteLegend } from '@visactor/vchart/esm/component/legend';
import { registerTooltip } from '@visactor/vchart/esm/component/tooltip';
import { registerDomTooltipHandler } from '@visactor/vchart/esm/plugin/components/tooltip-handler';
import { registerCartesianCrossHair } from '@visactor/vchart/esm/component/crosshair';
import { registerLabel } from '@visactor/vchart/esm/component/label';
import { registerAnimate } from '@visactor/vchart/esm/plugin/other';
import { registerBrowserEnv } from '@visactor/vchart/esm/env';

VChart.useRegisters([
  // chart
  registerBarChart,
  // axes
  registerCartesianBandAxis,
  registerCartesianLinearAxis,
  // components
  registerDiscreteLegend,
  registerTooltip,
  registerDomTooltipHandler,
  registerCartesianCrossHair,
  registerLabel,
  // animation + env
  registerAnimate,
  registerBrowserEnv
]);

const spec = {
  type: 'bar',
  data: [
    {
      id: 'sales',
      values: [
        { product: 'Widget A', revenue: 420 },
        { product: 'Widget B', revenue: 310 },
        { product: 'Widget C', revenue: 580 },
        { product: 'Widget D', revenue: 245 }
      ]
    }
  ],
  xField: 'product',
  yField: 'revenue',
  title: { text: 'Revenue by Product' },
  legends: { visible: true }
};

const vchart = new VChart(spec, { dom: 'container' });
vchart.renderAsync();
```
